# ETF方向与执行统一整改

2026-11-17用户授权：AI通过skills判断轮动，策略性指标不机械否决方向；测试通过、独立复查后上线。

## 运行链路

OCTOP五轮任务 → 统一共享采集 → 冻结板块、股票与ETF关联事实 → AI方向及显式ETF选择 → 单一版本化候选评价 → 必要执行核验 → 报告与节点同事务落库 → 共享补价 → T+1模拟成交。

### 候选和采集

- `stage2/penetration.py`的`etf-direction-first-v2`为唯一新入场评价；`worker.publish_round`保存同一结果供工作台、QQ及模拟使用。
- AI的`etf_choices`只允许来自冻结关联池，最多3只、可明确为空；未提交或引用错误标待核验。主板占比、暴露、核心股集中度、涨幅、均线等检查保留来源与数值，标`REFERENCE`。
- 新入场继续核验产品身份、实际交易规则、单位、上市交易状态及可用同日报价。产品涨跌幅比例按核验资料读取。待复核暂停新开仓及待买成交，LIVE发布和成交事务均读取当前已发布映射；已持仓退出使用原周期冻结规则。
- 目录缺权重属于资料覆盖缺口。有已核验的显式板块—指数关系时可以展示关联，未知暴露保持未知；不根据名称猜测关系。
- 股票覆盖使用股票研究报价。`etf_statistics`及维护任务按可识别的研究产品选择目标，不再以执行资格作为历史行情采集前提，沿用现有任务预算。

### 判断和解释

- `research_facts.py`提供`scoped-facts-v1`：每条事实含范围、对象、源时间、引用和程序计算结果。AI通过`fact_refs`引用，数字由程序呈现。
- 不同口径分别是已采集板块、已采集且对齐A股、单板块成员、单只股票及ETF，禁止将单板块比例写成全市场比例。
- 新解释中的未绑定事实数字、非法引用只使对应板块进入`UNKNOWN`复核，原提交保留。未来风险条件和已有代码/日期引用独立处理。
- 每板块至少有带来源的事实摘要，深度解释仍有预算上限；QQ优先显示执行节点和持仓对应板块。

### 成交补价

- `pending_quotes.py`由原`stage2.schedule`唯一worker执行，归属最近一个已发布的OCTOP轮次，无新增cron。
- 轮后30/120/300秒至多3次共享ETF批报价，理论日上限15次。真实请求间隔和日志在数据库保存；失败、恢复和重启不重置预算。
- 2026-11-21起（`CLAUDE.md`第33条）：当日最新一轮为`FAILED`时，该轮自己的3次预算从计划时刻起按同样间隔为已存在的减仓/清仓订单补价，
  结果带`failed_round=true`、`report_id=null`；买单不走失败轮次，这次取价只刷新这些卖单所在ETF的报价，其余报价保持原样。
  只有当日最新一轮（含仍在运行的）是失败轮次时才适用。失败轮次的预算用完或没有待价卖单时，仍按最近一个已发布轮次处理。
- 仅交易时段且实际可买/可卖的待价格订单发起请求；午休、收盘、非交易日和等待T+1不补价。旧订单可在当日新的OCTOP轮次下继续推进。
- `DISABLE_EXTERNAL_PROVIDER_HTTP`在调度、补价入口和物理请求前均生效；禁用时不建请求预算、不回源，已保存的共享行情仍可按原规则消费。
- 重启可复用已保存批次；共享快照保留板块、股票和IOPV原时间。成交严格采用节点后的有效价格，唯一事件键和订单规则避免重复记账。

### 展示和历史

资料待补、关联观察、AI已选、执行限制分别展示。执行限制给具体原因；计数区分去重ETF数和板块关联条数。节点区分等待价格、T+1、交易日历和资金不足。原始报告、旧订单和历史成交不重写。
