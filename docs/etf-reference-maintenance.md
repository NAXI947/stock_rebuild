# ETF穿透资料维护

2026-11-17 用户授权按统一采集拓扑整改并上线，改在受控盘中窗口执行，并按资料类型分频。明确不引入100%准确率或覆盖率门槛。维护是独立资料任务，不产生Hermes判断、交易节点或模拟成交。

## 自动化与周期

OCTOP独立「ETF资料维护」专家配置两个工作日任务，Asia/Shanghai：10:00主维护（market）、14:15缺项复核（retry）。窗口分别为10:00—10:15、14:15—14:27，每个任务最多运行12分钟。盘中只取已完成交易日资料；交易日历过滤休市日，按执行日期与mode去重。14:15只处理持久待补及当日主维护失败项，没有待补时不调用供应商。原研判专家及09:35、10:35、13:05、14:05、14:30任务保持不变。

| 资料 | 周期与策略 |
|---|---|
| 股票及ETF目录、上市状态、跟踪指数 | 默认每7天检查；缺批次时补齐。明确的股票身份缺口可提前刷新股票目录，复用底层6小时缓存 |
| 板块成员 | 默认每7天滚动检查；新方向、缺项进入待补；持仓/活动方向优先，轮换新发现、待补和既有资料，每次最多8板块、每板块8页 |
| 指数成分与权重 | 每7天检查最新可用月度来源；缺项按待补处理；每次最多8指数，保留真实权重日期 |
| ETF历史成交额、复权资料、ADV | 每交易日10:00检查上一已完成交易日的20日窗口；优先持仓及候选，另留轮换名额，每次最多12产品。14:15仅复核当日上午失败产品，完整窗口不再请求 |
| ETF规模/份额 | 每交易日10:00检查最近完成交易日及持久待补日期；先吸收已存且核验通过的批次，再请求缺项。14:15复核失败日期，记录来源日、取得时间与有效期 |
| 交易日历 | 每周检查，兼容已存未来年度与发布文件；每轮只读本地版本 |
| 产品官方规则依据与首次核验 | 已核验材料每周摘要检查；变动标记待复核。逐字段证据经审阅导入后，由同维护任务优先回核并发布，不新增采集时钟 |
| ETF盘口价差 | 每轮共享采集增加一次有界深度批量请求；缺失仅影响对应交易事实 |

周期表示维护任务检查周期；低频权重和官方文件仍保留来源实际日期。新产品进入目录后先标记待核验，不构造交易规则。

首次核验与重新核验使用[受控证据导入入口](etf-product-verification.md)。审阅者可如实记录AI-assisted review；导入仅保存PENDING。维护在常规映射补采前受理已导入材料，共用120请求/12分钟预算，回核成功后原子发布。官方周检和首次核验按真实来源时间共享摘要回执，旧缓存不得覆盖新回核。待复核期间暂停新开仓和待买成交，已有持仓按冻结规则退出。

## 执行与失败处理

维护复用现有单worker和有界队列。每任务最多120次实际外部请求、12分钟。准备时和每次外部请求前后校验维护时段、发布暂停、租约及外部采集开关；统一请求预算包含底层分页与补跑，不因时段迁移绕过既有采集规则。OCTOP模型最多24次调用，只能使用维护prepare/status两个工具。原研究专家仍是3个研究工具、8次模型调用。

资料按项更新；成员新结果不完整时保留旧可用成员，新权重依据待核验时保存pending_weights并沿用旧完整权重。全部来源失败则沿用旧映射，成功项可发布独立版本。缺资料只影响对应标的事实，不中止全轮研判。取消或失去租约时不激活新映射。

### 成员资料回退与新增方向（2026-11-16修复）

目标日成员不可用或不完整时，优先比较已发布的可用名单与本地保存的历史成员页，使用日期最新且完整核验的名单。历史页须通过分页、总数、重复代码、股票身份和来源时间检查；沿用原资料日期与源批次，不改成当天名单。回退只读取已入库资料，不增加外部日期探测请求。

14:15复核只处理失败或未完成的资料键，已到期检查成功的成员不强制重采。读取已有完整成员缓存优先，保留真实来源日期和分页核验；复核失败继续保留可用旧名单并明确待补。

只有实际存在可用成员时才反馈“沿用历史名单”，同时记录来源日期。无可用名单则标记“待补”；部分新页保留缺口，不覆盖完整旧名单。后来取得完整新名单时，以新版本替换并接入下一轮个股行情和参与宽度分析。

成员维护仍受每轮8板块、每板块8页及任务总预算限制。维护记录保存目标尝试进度，缺项复核与后续维护窗口继续推进待补方向，避免固定排序长期遗漏新增板块。超出本轮范围的对象明确记为后续待补，不伪装为已沿用。

持仓/活动方向与其他方向分别保存循环游标；其他方向存在时每轮至少保留2个名额。未取得名单的新板块进入最多256项的持久待补列表，即使后续离开热点榜也继续轮换；容量溢出单独反馈数量。历史缓存最多检查8个来源日期，分页与日期范围都有界。

新增板块仍可能暂缺来源资料，新增成分股也需等待供应商发布完整名单；反馈显示相应待补或沿用日期，下一轮维护继续处理。无需为新成员增加逐股HTTP请求，正常批量行情与已发布映射共同产生个股证据。

历史行情比较独立读取截止时间前最近8份已发布报告中的板块观测，不以是否进入活动交易方向为前提。同日差值按百分点展示；跨日保留来源日期作为背景。交易阶段与模拟规则保持原契约。

映射存入追加式maintained_mappings，读取时按available_at截止，文件作为后备。旧报告、冻结输入、周期、成交记录不重算。交易日历同样按取得时点读取。新旧基础资料存储格式兼容。

完整资料日历供统计和研判读取；已有LIVE账本提交报告或行情时，经`stage2/execution_calendar.py`保留该运行空间原有全部执行日期，仅加入账本水位之后的新日期。投影与提交共用事务锁，保留已有T+1日期；历史扩容不会改写旧报告或成交。FROZEN回放与底层`_store`历史日历拒绝规则保持原样。

终态与QQ Outbox在同一事务保存；QQ失败只重投反馈。OCTOP保留原生任务、会话和模型用量。反馈列出映射规模、版本、更新/沿用/待核验项、来源日期和日历范围。

## 升级与数据归属

发布先drain并等待在途任务收尾，再更新应用和OCTOP配置。配置工具在官方embedded runtime及暂停调度器内，复用原18:00与21:00的任务ID改为10:00与14:15，禁用旧08:45任务并保留历史。先保存全部暂停状态，全部更新成功后统一启用；异常保持暂停，允许重新执行配置。旧mode不再创建任务，status和历史反馈继续可读。

股票资料、ETF目录、成员、权重、规模、规则通过同一维护入口生成追加映射版本；行情和ETF历史统计独立存储，研判时按截止时间只读叠加。原06:00股票日更继续共用有界worker队列，不重复采集ETF资料。旧StatisticsRefresh轮询器已退役；任何模式直接实例化都会返回明确配置错误，worker不再启动第二条统计采集路径。页面、GET和QQ重投不触发采集。

QQ结果同时标明执行日与资料日，规模按日批次计数，区分未发布、连接、字段、日期和分页异常。终态反馈说明资料缺口对标的的影响；按已保存维护结果投递，不把维护回执当作Hermes运行健康检查。

2026-11-17盘中验收补充：成功取得的ETF目录中，产品范围、尚未适配的指数后缀和缺失指数关联单独保存为catalog_review，附来源批次、分类计数和最多5条样例；这些人工整理项沿用周检周期，不重复回源。结构或请求状态错配才进入接口待补。当前指数适配仍为SH/SZ/CSI，CNI等范围的扩展需另行完成指数及官方依据适配。

完整参考日历用于研究和历史统计；已有LIVE执行账本使用原冻结日历，并仅添加水位之后的已核验日期。此投影在publish/apply_quotes的原事务及命名空间锁内执行，_store的历史保护和FROZEN回放行为保持原契约。行情或发布失败时，已保存的Redis/QQ通知分别按原Outbox租约及次数预算继续处理；发布暂停仍阻止投递。日历兼容和通知隔离不自动重跑已经失败的研判。
