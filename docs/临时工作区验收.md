# 临时工作区与下载验收

应用 API 和 worker 在各自已挂载的 APP_TMP_ROOT 下启动时检查一次，以后每 15 分钟检查。只回收已登记任务目录且可取得独占租约的工作区。每次最多尝试 128 个任务，统计受管文件大小和条目。已配置的 2 GiB 默认预算是应用写入预算，文件系统硬配额由独立配置及实测决定。Nginx 的目录由 Nginx 自身管理。

认证后的 `GET /api/v2/backtests/{id}/download` 下载已保存的手动回测结果，不重算或回源。响应打开期间保留任务租约，下载结束或中断时 WSGI 关闭响应，回收临时副本。空间或预算不足返回 507，原结果仍可通过工作台读取。

调测运行命令如下。

```bash
cd /opt/workspace/stock-v4
runtime=/opt/workspace/stock-v4-runtime
STAGE1_TEST_ROOT="$runtime/test-tmp" \
  "$runtime/stage2-venv/bin/python" -B -m unittest discover -s tests -p test_stage1_runtime.py -v
```

C05 实测将正在读取的下载文件日期拨旧，同时强制终止另一个已落盘任务。周期检查移除无租约任务，下载任务仍可读。关闭响应后下载目录消失，受管字节恢复为零。

C13 在调测服务器以只读根目录及独立网络启动 Stock V4 Web 镜像和本地回显上游。默认 Nginx 配置转发了分两次发送的 1 MiB 请求，内容摘要一致，临时路径无落盘。超过 8 MiB 1 字节时返回 413。在另一个容器仅将请求内存缓冲改为 16 KiB，暂停同一上传时观察到打开的 `/app/tmp/web/client_body/0000000001 (deleted)`，请求完成后文件描述符关闭且目录无文件残留。默认代理响应缓冲关闭，直接转发到客户端。该试验没有修改生产缓冲配置。
